# Config schema reference

This page tracks the actual schema in `src/core/config/config-schema.ts`.
Every top-level section is optional. When omitted, Talon applies schema defaults.

## Root fields

```yaml
logLevel: info
dataDir: data
```

| Field | Type | Default | Description |
|---|---|---|---|
| `logLevel` | `trace \| debug \| info \| warn \| error \| fatal` | `info` | Pino log level |
| `dataDir` | string | `data` | Root runtime data directory |

## `sandbox`

```yaml
sandbox:
  runtime: docker
  image: talon-sandbox:latest
  maxConcurrent: 3
  networkDefault: off
  idleTimeoutMs: 1800000
  hardTimeoutMs: 3600000
  resourceLimits:
    memoryMb: 1024
    cpus: 1
    pidsLimit: 256
```

| Field | Type | Default | Description |
|---|---|---|---|
| `runtime` | `docker \| apple-container` | `docker` | Sandbox runtime |
| `image` | string | `talon-sandbox:latest` | Sandbox image |
| `maxConcurrent` | integer ≥ 1 | `3` | Max concurrent sandboxed runs |
| `networkDefault` | `off \| on` | `off` | Default network access |
| `idleTimeoutMs` | integer ≥ 0 | `1800000` | Idle timeout in ms |
| `hardTimeoutMs` | integer ≥ 0 | `3600000` | Hard timeout in ms |

| `resourceLimits.cpus` | number | `1` | CPU limit per sandbox |
| `resourceLimits.pidsLimit` | integer | `256` | PID limit per sandbox |

## `personas[]`

```yaml
personas:
  - name: assistant
    model: claude-sonnet-4-6
    provider: claude-code
    systemPromptFile: personas/assistant/system.md
    skills:
      - web-search
    subagents:
      - session-summarizer
    capabilities:
      allow:
        - memory.access:thread
        - net.http:egress
        - schedule.manage:own
      requireApproval:
        - db.query:own
    mounts:
      - source: /srv/notes
        target: /workspace/notes
        mode: ro
    maxConcurrent: 2
```

| Field | Type | Default | Description |
|---|---|---|---|
| `name` | string | required | Persona name |
| `model` | string | `claude-sonnet-4-6` | Model identifier |
| `provider` | string | — | Optional provider override |
| `systemPromptFile` | string | — | Path to `system.md` |
| `skills` | string[] | `[]` | Attached skill names |
| `subagents` | string[] | `[]` | Allowed sub-agent names |
| `capabilities.allow` | string[] | `[]` | Allowed capability labels |
| `capabilities.requireApproval` | string[] | `[]` | Approval-gated capability labels |
| `mounts` | array | `[]` | Sandbox mounts |
| `maxConcurrent` | integer ≥ 1 | — | Optional per-persona concurrency cap |

|---|---|---|---|

## `channels[]`

```yaml
channels:
  - name: my-telegram
    type: telegram
    enabled: true
    showToolCalls: true
    config:
      botToken: ${TELEGRAM_BOT_TOKEN}
      pollingTimeoutSec: 30
      allowedChatIds:
        - "123456789"
```

| Field | Type | Default | Description |
|---|---|---|---|
| `type` | `telegram \| whatsappBusiness \| whatsappBaileys \| slack \| email \| discord \| terminal` | required | Channel connector type |
| `name` | string | required | Channel name |
| `config` | object | `{}` | Connector-specific config |
| `tokenRef` | string | — | Optional token reference |
| `enabled` | boolean | `true` | Enable channel at startup |
| `showToolCalls` | boolean | — | Optional per-channel tool-call messages |

Notes:

- The config schema accepts `whatsappBusiness`, not the legacy CLI alias `whatsapp`.
- `showToolCalls` is optional in config; when omitted the runtime behaves as `false`.

## `voice`

Browser voice is opt-in and disabled by default. It starts an HTTP listener
for the authenticated WebRTC UI on `voice.host` (loopback by default) and uses
the ordinary durable queue and `AgentRunner` path for backend work.

```yaml
voice:
  enabled: false
  host: 127.0.0.1
  port: 0
  # publicHost: voice.example.com
  accessTokenRef: voice
  liveApiKeyRef: openai
  # provider: openai-compatible
  # model: gpt-live-1
  # persona: assistant
  voice: marin
  allowedTransportTypes:
    - webrtc
  allowedOrigins: []
  allowedToolNames: []
  allowedMcpServerNames: []
```

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `false` | Start the browser voice runtime |
| `host` | string | `127.0.0.1` | Node listener host or address; defaults to loopback and accepts configured wildcard or IPv6 addresses |
| `port` | integer `0..65535` | `0` | Listener port; `0` selects an available port |
| `publicHost` | non-empty string | — | Public HTTPS host; adds `https://<publicHost>` to allowed origins |
| `accessToken` | string | — | Direct access token; prefer `accessTokenRef` and an environment-backed auth provider |
| `accessTokenRef` | non-empty string | `voice` | `auth.providers.<name>.apiKey` slot used for browser login |
| `liveApiKeyRef` | non-empty string | `openai` | `auth.providers.<name>` slot used by the live voice provider |
| `provider` | non-empty string | selected persona provider | Backend provider name; when enabled its implementation type must be `openai-compatible` |
| `model` | non-empty string | `gpt-live-1` at bootstrap | Live voice model; the persona's `model` remains the backend model |
| `persona` | non-empty string | first configured persona | Persona used for backend policy and execution |
| `voice` | non-empty string | `marin` | Server-selected live output voice |
| `usdPerMinute` | finite number ≥ 0 | — | Optional operator-supplied voice rate used for a duration estimate; there is no default |
| `instructions` | string | `You are Talon, a helpful voice assistant.` | Live provider instructions |
| `allowedTransportTypes` | non-empty string[] | `['webrtc']` | Transport allowlist; current runtime accepts only `webrtc` |
| `allowedOrigins` | URL[] | `[]` | Explicit browser origins; `publicHost` contributes an HTTPS origin |
| `allowedToolNames` | non-empty string[] | `[]` | Voice tool allowlist, still subject to persona policy |
| `allowedMcpServerNames` | non-empty string[] | `[]` | MCP allowlist; only proven/configured servers can be used |
| `maxSessionLifetimeMs` | integer ≥ 1000 | `900000` | Maximum voice session lifetime |
| `maxContextChars` | integer `256..256000` | `32000` | Bound for voice context passed to the live provider |
| `maxConcurrentSessions` | integer ≥ 1 | `1` | Active browser session limit |
| `maxSessionCreations` | integer ≥ 1 | `5` | Session creations allowed per window |
| `sessionCreationWindowMs` | integer ≥ 1000 | `60000` | Session creation rate-limit window |
| `heartbeatIntervalMs` | integer ≥ 1000 | `15000` | SSE heartbeat interval |

When `voice.enabled` is true, Talon requires a configured persona and an
enabled provider whose implementation type is `openai-compatible`. The
configured access token is resolved from `voice.accessToken`, then the
`accessTokenRef` provider, then the global `auth.apiKey`. Use HTTPS through a
reverse proxy for non-local browsers, preserve `Host` and `Origin`, and send
`X-Forwarded-Proto: https` so secure cookies and origin checks reflect the
public connection. If that proxy runs outside the daemon's network namespace,
set `voice.host` to a reachable interface or wildcard address and restrict
network exposure at the proxy or firewall. `voice.model` controls the live
voice provider only; it does not change the persona backend model.

Voice stores bounded session text, outputs, usage, and lifecycle state in
SQLite. Raw audio is not represented in the voice schema, and provider-side
cloud retention remains governed by the provider account and API settings.
When `usdPerMinute` is configured, voice cost is estimated from cumulative
provider-reported seconds. Final provider usage does not confirm billing, so
the status remains `estimated`; when that rate has known seconds but an
incomplete close, the status is `incomplete`, while an omitted rate is
`unavailable`. Backend cost comes only from AgentRunner run accounting and
remains separate.

## `agentRunner`

```yaml
agentRunner:
  defaultProvider: claude-code
  providers:
    claude-code:
      enabled: true
      command: claude
      contextWindowTokens: 200000
      contextManagement:
        enabled: true
        triggerMetric: cache_read_input_tokens
        thresholdRatio: 0.5
        recentMessageCount: 10
        summarizer: session-summarizer
    codex-cli:
      enabled: false
      command: codex
      contextWindowTokens: 400000
      contextManagement:
        enabled: true
        triggerMetric: cache_read_input_tokens
        thresholdRatio: 0.8
        recentMessageCount: 10
        summarizer: session-summarizer
      options:
        defaultModel: gpt-5.4
```

| Field | Type | Default | Description |
|---|---|---|---|
| `defaultProvider` | string | `claude-code` | Default foreground provider |
| `providers` | record | built-in `claude-code` entry | Provider configs |

### `agentRunner.providers.<name>`

```yaml
providers:
  codex-cli:
    enabled: false
    command: codex
    contextWindowTokens: 400000
    options:
      defaultModel: gpt-5.4
    contextManagement:
      enabled: true
      triggerMetric: cache_read_input_tokens
      thresholdRatio: 0.8
      recentMessageCount: 10
      summarizer: session-summarizer
```

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `false` | Enable the provider |
| `command` | string | required | CLI command |
| `contextWindowTokens` | integer ≥ 1000 | `200000` | Context window size |
| `options` | object | — | Provider-specific options |
| `contextManagement.enabled` | boolean | `false` | Enable rotation |
| `contextManagement.triggerMetric` | enum | — | Required when enabled |
| `contextManagement.thresholdRatio` | number 0-1 | — | Required when enabled |
| `contextManagement.recentMessageCount` | integer ≥ 0 | `10` | Messages retained after rotation |
| `contextManagement.summarizer` | string | — | Required when enabled |

Built-in schema default:

```yaml
agentRunner:
  defaultProvider: claude-code
  providers:
    claude-code:
      enabled: true
      command: claude
      contextWindowTokens: 200000
      contextManagement:
        enabled: true
        triggerMetric: cache_read_input_tokens
        thresholdRatio: 0.5
        recentMessageCount: 10
        summarizer: session-summarizer
```

## `backgroundAgent`

```yaml
backgroundAgent:
  enabled: true
  maxConcurrent: 3
  defaultTimeoutMinutes: 30
  defaultProvider: claude-code
  providers:
    claude-code:
      enabled: true
      command: claude
      contextWindowTokens: 200000
    codex-cli:
      enabled: false
      command: codex
      contextWindowTokens: 400000
      options:
        defaultModel: gpt-5.4
```

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `true` | Enable background agents globally |
| `maxConcurrent` | integer 1-10 | `3` | Max concurrent background tasks |
| `defaultTimeoutMinutes` | integer 15-480 | `30` | Default timeout |
| `defaultProvider` | string | `claude-code` | Default background provider |
| `providers` | record | built-in `claude-code` entry | Provider configs |
| `claudePath` | string | — | Legacy shortcut for creating a `claude-code` provider when no explicit providers are set |

`backgroundAgent.providers.<name>` uses the same provider shape as `ProviderConfigSchema`: `enabled`, `command`, `contextWindowTokens`, and optional `options`.

## `subagents`

```yaml
subagents:
  memory-groomer:
    model:
      - provider: ollama
        name: qwen3-30b
      - provider: anthropic
        name: claude-haiku-4-5-20251001
```

| Field | Type | Default | Description |
|---|---|---|---|
| `subagents.<name>.model` | array | — | Ordered model failover chain for a sub-agent |
| `model[].provider` | `anthropic \| openai \| google \| ollama` | required | AI SDK model provider slot |
| `model[].name` | string | required | Model name for that provider |
| `model[].maxTokens` | integer > 0 | manifest value | Optional max output tokens |
| `model[].timeoutMs` | integer ≥ 1000 | manifest value | Optional per-model timeout |
| `model[].providerOptions` | object | — | Vendor-specific options, effective only for `ollama` passthrough |

`subagents.*.model[].provider` is not an agent runtime provider. `codex-cli`,
`claude-code`, `gemini-cli`, and `openai-compatible` are invalid here; use
`ollama` for OpenAI-compatible sub-agent endpoints.
