# Host tools reference

Talon exposes 7 built-in tools to agents through the internal MCP server `__talond_host_tools`.
At the MCP layer the tool names use underscores, for example `memory_access`.
Inside the daemon the corresponding internal names use dots, for example `memory.access`.

Every host-tool call is:

- filtered by the persona's capability labels before the tool is even listed
- checked again at the bridge before execution
- executed on the host, not inside the sandbox

---

## `schedule_manage`

Internal tool: `schedule.manage`

Capability labels:

- `schedule.manage:own`

Creates, updates, cancels, deletes, or lists schedules owned by the current persona.

| Parameter | Type | Notes |
|---|---|---|
| `action` | `create \| update \| cancel \| delete \| list` | Required |
| `scheduleId` | string | Required for `update`, `cancel`, and `delete` |
| `cronExpr` | string | Required for `create`; optional for `update`; must be a 5-field cron expression |
| `label` | string | Optional human-readable label |
| `prompt` | string | Inline prompt; mutually exclusive with `promptFile` |
| `promptFile` | string | Prompt alias from the persona's `prompts/` directory; mutually exclusive with `prompt` |

Notes:

- This tool currently manages cron schedules only.
- `cancel` disables a schedule.
- `delete` removes it permanently.
- `promptFile` resolves a basename like `memory-grooming`, not a filesystem path.

## `channel_send`

Internal tool: `channel.send`

Capability labels:

- `channel.send:*`
- `channel.send:<channel-name>`

Sends a Markdown message to another Talon channel.

| Parameter | Type | Notes |
|---|---|---|
| `channelId` | string | Required; this is the configured channel name |
| `content` | string | Required Markdown body |
| `replyTo` | string | Optional message ID to send this as a native reply to: the `(id …)` value from a `[Replying to …]` or `[Reaction: …]` header. Ignored on channels without native replies |
| `externalChatId` | string | Optional explicit recipient chat on the target channel |
| `attachments` | array | Optional files to attach, each `{ path, filename?, mimeType?, caption? }`. Needs the `channel.attach` capability. `path` must be absolute and inside the run's thread `artifacts/` directory or an `attachments.outbound.allowedRoots` entry. When given, `content` may be empty. Telegram only for now |

Notes:

- The agent does not pass a thread ID directly; Talon resolves the current thread context for the target channel.
- Output is converted to the target connector's native format automatically.
- A `replyTo` reply is always sent as a native reply, regardless of the connector's `replyToTrigger` setting.
- Attachments are validated before anything is sent: a refused item fails the whole call with a code (`capability_denied`, `attachments_disabled`, `channel_unsupported`, `too_many_files`, `invalid_request`, `path_not_absolute`, `outside_allowed_roots`, `symlink_escape`, `denied_path`, `not_found`, `is_directory`, `special_file`, `empty_file`, `too_large`, `mime_not_allowed`, `read_failed`). The type is sniffed from the file contents.
- With attachments, the text goes first (carrying the reply), then one message per attachment. If an upload fails after the text arrived, the result lists `attachments: [{ index, filename, status, error? }]` and the recipient gets a short notice. See [ADR 0003](../adr/0003-outbound-attachments.md).

## `channel_react`

Internal tool: `channel.react`

Capability labels:

- `channel.react:*`

Places an emoji reaction on a message in the current conversation, or removes Talon's reaction from it. Supported on Telegram, WhatsApp Baileys and WhatsApp Business; other channels return an error.

| Parameter | Type | Notes |
|---|---|---|
| `emoji` | string | A single emoji. Required unless `remove` is `true` |
| `messageId` | string | Optional. Leave out to react to the message that started the run. Otherwise the ID of another message in this conversation: an `(id …)` value from a `[Replying to …]` or `[Reaction: …]` header, or an ID from `list` |
| `remove` | boolean | Optional; removes Talon's reaction instead of adding one |
| `list` | boolean | Optional; does not react, and returns the conversation's recent messages (`messageId`, `from`, `text`), newest first |

Notes:

- The tool takes no channel or chat argument: it only acts on the conversation the run belongs to.
- `channel.react` is a separate capability from `channel.send`. A persona with only `channel.send` cannot react.
- To acknowledge without sending text, react and then make the final response exactly `NO_REPLY`. A response that is only that word is not delivered to the chat.
- Telegram accepts only its standard reaction set. An emoji outside it returns an error that lists the allowed emoji.
- A run that was not started by a channel message (a schedule, a user reaction, a background agent) has no default target and must pass `messageId`.
- An explicit `messageId` must be known to the message ledger for this conversation. An unknown ID is not sent to the channel: the tool returns an error listing the recent messages and their real IDs. The numbers stored in the `messages` table are delivery keys (on Telegram an `update_id`), not message IDs; the tool does accept a stored message's own `messages.id`.
- Delegated (A2A) runs cannot react.

## `memory_access`

Internal tool: `memory.access`

Capability labels:

- `memory.access:thread`

Reads and writes per-thread memory items.

| Parameter | Type | Notes |
|---|---|---|
| `operation` | `read \| write \| delete \| list` | Required |
| `key` | string | Required for `read` and `delete`; optional for `write` |
| `value` | any | Required for `write`; non-string values are JSON-stringified |
| `namespace` | string | Optional; maps to the memory item type |

Notes:

- When `write` omits `key`, Talon generates a UUID.
- Supported namespaces map to `fact`, `summary`, and `note`.
- Unknown namespaces fall back to `note`.

## `net_http`

Internal tool: `net.http`

Capability labels:

- `net.http:egress`

Proxies outbound HTTP and HTTPS requests through the host.

| Parameter | Type | Notes |
|---|---|---|
| `method` | `GET \| POST \| PUT \| PATCH \| DELETE \| HEAD` | Required |
| `url` | string | Required |
| `headers` | object | Optional string header map |
| `body` | string | Optional request body |
| `timeoutMs` | number | Optional; defaults to `30000`, capped at `120000` |

Notes:

- Only `http:` and `https:` URLs are allowed.
- Domain allowlisting is enforced by the host-side handler.
- An empty allowlist means the capability label is the only gate.

## `db_query`

Internal tool: `db.query`

Capability labels:

- `db.query:own`

Runs restricted read-only SQL queries against the Talon SQLite database.

| Parameter | Type | Notes |
|---|---|---|
| `sql` | string | Required; must be a simple `SELECT` statement |
| `params` | array | Optional prepared-statement parameters |
| `limit` | number | Optional; defaults to `100`, maximum `1000` |

Allowed tables:

- `memory_items`
- `schedules`
- `messages`
- `threads`

Restrictions:

- only `SELECT` is allowed
- `UNION`, `EXCEPT`, `INTERSECT`, CTEs, and subqueries are rejected
- Talon auto-injects thread and persona scoping where applicable
- the query runs through a read-only SQLite connection

## `subagent_invoke`

Internal tool: `subagent.invoke`

Capability labels:

- `subagent.invoke`

Runs a named sub-agent synchronously and returns its structured result.

| Parameter | Type | Notes |
|---|---|---|
| `name` | string | Required sub-agent name |
| `input` | object | Optional JSON object passed through to the sub-agent |

Built-in sub-agents shipped in this repo:

| Name | Model | Purpose |
|---|---|---|
| `session-summarizer` | `claude-sonnet-5-5` | Compress long conversation history for session resumption |
| `memory-retriever` | `claude-haiku-5-5`          | Retrieve relevant memory items for a query |
| `memory-groomer` | `claude-haiku-5-5`          | Consolidate and prune memory entries |
| `file-searcher` | `claude-haiku-5-5`          | Search files and return ranked snippets |

## `background_agent`

Internal tool: `subagent.background`

Capability labels:

- `subagent.background`

Starts and manages long-running background agent tasks.

| Parameter | Type | Notes |
|---|---|---|
| `action` | `spawn \| status \| cancel \| result \| profiles` | Required |
| `prompt` | string | Required for `spawn` |
| `taskId` | string | Used by `status`, `cancel`, and `result` |
| `provider` | string | Optional provider override for `spawn` |
| `profile` | string | Optional persona profile name for `spawn` |
| `workingDirectory` | string | Optional working directory for `spawn` |
| `timeoutMinutes` | number | Optional timeout override for `spawn`; minimum effective value is 15 |

Notes:

- Call `action: "profiles"` first if the agent needs to discover which persona profiles are available.
- A `profile` uses another loaded persona's prompt, skills, model, provider, and capabilities.
- Background tasks return a task ID immediately and later deliver completion back into the originating thread.
