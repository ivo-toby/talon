# Scheduling

Talon's public scheduling surface is cron-based.
The scheduler polls for due schedules, enqueues them as normal queue items, and the agent handles them like any other message.

## Enable schedule management

Grant the schedule capability to the persona:

```yaml
personas:
  - name: assistant
    capabilities:
      allow:
        - schedule.manage:own
```

## The host tool name

The MCP tool exposed to the agent is `schedule_manage`.
Inside the daemon its internal name is `schedule.manage`.

Supported actions:

- `create`
- `update`
- `cancel`
- `delete`
- `list`

Supported fields:

- `action`
- `scheduleId`
- `cronExpr`
- `label`
- `prompt`
- `promptFile`

Important constraints:

- only cron expressions are supported by this tool
- `prompt` and `promptFile` are mutually exclusive
- `promptFile` is a prompt alias from the persona's `prompts/` directory, not an arbitrary path

## Where a scheduled message is delivered

A scheduled run reaches the user only when the agent calls `channel_send`. Where that message goes depends on how the schedule was created:

| Schedule created | Delivered to |
|---|---|
| By the agent, with `schedule_manage`, in a chat | That chat |
| By the agent, inside a Telegram topic | That topic |
| With `talonctl add-schedule` | Nowhere by default: the agent must pass `externalChatId` |

Talon records the conversation a schedule was created in and routes `channel_send` back to it, as long as the agent does not pass `externalChatId`. An explicit `externalChatId` always wins, so a persona that has learned one fixed chat ID will send every reminder there. The log line `channel.send: message sent successfully` shows the `recipient` and the `recipientSource` (`schedule origin`, `externalChatId argument` or `current thread`).

To deliver a CLI-created schedule into a Telegram topic, put the topic's thread key in its prompt, for example "send the result with `externalChatId` `-1004452318413:42`". Send `/chatid` inside the topic to get that key.

## Using `promptFile`

If a persona has:

```text
personas/assistant/prompts/morning-summary.md
```

then the schedule should use:

```yaml
promptFile: morning-summary
```

At execution time the scheduler resolves that alias through the persona loader.

## CLI scheduling commands

The CLI command `add-schedule` also creates cron schedules only:

```bash
npx talonctl add-schedule \
  --persona assistant \
  --channel my-telegram \
  --cron "0 9 * * 1-5" \
  --label "Morning summary" \
  --prompt "Summarize what I should focus on today."
```

List and remove them with:

```bash
npx talonctl list-schedules
npx talonctl list-schedules --persona assistant
npx talonctl remove-schedule <schedule-id>
```

## Scheduler config

```yaml
scheduler:
  tickIntervalMs: 5000
```

The default tick interval is 5 seconds.
