# Incoming SIP with Asterisk

Talon's incoming SIP receiver is disabled by default. When explicitly enabled,
it accepts only an OpenAI `live.transport.incoming` event whose `data.type` is
`sip` and whose `data.session_id` is present. The Standard Webhooks signature is
verified over the bounded raw request before JSON parsing. That proves the
provider delivery; it does not authenticate the caller.

Caller authority comes from a separate short-lived Ed25519 assertion generated
by an authenticated Asterisk PJSIP endpoint. Talon verifies the configured
issuer, key, audience, signature, endpoint subject mapping, nonce, call binding,
and time bounds. Caller ID, `From`, `To`, and ordinary SIP headers never choose
an owner, persona, capability, or provider session. A duplicated, altered,
missing, expired, revoked, or unmapped assertion is denied.

The reference files are [the restricted dialplan](../../examples/voice/asterisk/extensions.conf.example),
[the PJSIP shape](../../examples/voice/asterisk/pjsip.conf.example), and [the
native Ed25519 AGI signer](../../scripts/voice/asterisk-sign-call.mjs). The
signer reads its private key from `TALON_SIP_PRIVATE_KEY_FILE`, queries the
server-owned `TALON_SIP_ENDPOINT_SUBJECT` and `TALON_SIP_CALL_BINDING` channel
variables through AGI (the dialplan populates them from `CHANNEL(endpoint)` and
`CHANNEL(uniqueid)`), and writes only bounded AGI protocol commands. It rejects
shell/AGI arguments and never logs the assertion or key. The caller channel
copies the assertion to a single-level inherited variable before `Dial`; the
outgoing `b()` pre-dial handler removes any inherited
`X-Talon-Voice-Assertion` and adds exactly one locally generated assertion.

Example configuration is intentionally incomplete and contains no usable key,
webhook secret, trunk, or owner mapping:

```yaml
voice:
  # Browser voice and incoming SIP are independently opt-in.
  sip:
    enabled: false
    host: 127.0.0.1
    port: 0
    path: /voice/sip/webhook
    standardWebhookSecretRef: openai-webhook
    issuer: operator-configured-issuer
    audience: talon-incoming-sip
    publicKeys: {}
    endpointMappings: {}
```

The durable boundary reserves a call, exact authority grant, and delivery
receipt in one SQLite `BEGIN IMMEDIATE` transaction. It uses the provider
session ID and assertion nonce for replay protection, allocates revisions from
the existing shared voice allocator, and persists an attempt marker before a
future call-control callback can accept anything. A timeout, crash, or network
failure becomes `unknown` and is never retried automatically. A duplicate
delivery returns the existing safe outcome without a second attempt.

The fixed engineering limits are 256 KiB raw webhook bytes, 32 pending receipt
work items, a 60-second original-event/proof admission window, a 5-second
deferred-decision budget, 10,000 retained decision rows, 50,000 receipts, and
10,000 grants. Cleanup can remove at most 100 rows per admission and only old,
expired/revoked, known-terminal call families. Pending, attempted, and unknown
tombstones remain and continue to deny new admission when storage saturates.

This is an offline authority and persistence boundary. The current stage does
not install Asterisk, provision keys, enable a Live project or trunk, preserve a
custom header on a real trunk, bridge media, or place/accept a paid call. Task
37 owns provider acceptance and attachment after this seam is reviewed.
