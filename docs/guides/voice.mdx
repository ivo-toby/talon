# Browser voice

Talon can expose an opt-in browser voice session at `/voice/`. The browser
uses WebRTC for the browser live audio path. Talon keeps authentication, policy,
the session lifecycle, and any delegated backend work on the daemon. An
independent incoming SIP webhook boundary is available only when explicitly
enabled; it does not replace the browser route or install a PBX.

## Requirements

- A persona whose configured provider is enabled. Voice backend work uses that
  persona's normal model and queue, including its provider's normal OAuth and
  native-tool restrictions.
- A voice access token and, when the live provider requires one, a live API
  key. Keep both in environment variables referenced by `auth.providers`.
- HTTPS for a browser reached through a network. Local loopback testing can
  use HTTP. The listener defaults to loopback; when a reverse proxy runs in a
  different VM, container, or network namespace, set `voice.host` to a
  reachable interface address (or `0.0.0.0`) and restrict network access.
- A reverse proxy that preserves the public `Host` and `Origin` headers and
  sends `X-Forwarded-Proto: https`. Talon uses that header when deciding
  whether to mark the authentication cookies `Secure` and when checking the
  same-origin read path.

## Configuration

The feature is disabled by default. This example contains no secret values:

```yaml
auth:
  providers:
    voice:
      apiKey: ${TALON_VOICE_ACCESS_TOKEN}
    openai:
      apiKey: ${OPENAI_API_KEY}

voice:
  enabled: true
  host: 127.0.0.1
  port: 8787
  publicHost: voice.example.com
  accessTokenRef: voice
  liveApiKeyRef: openai
  # provider: openai-compatible  # deprecated compatibility field; persona provider is authoritative
  model: gpt-live-1
  persona: assistant
  voice: marin
  # usdPerMinute: 0.00 # replace with a current provider rate; omitted means unavailable
  allowedOrigins:
    - https://voice.example.com
  allowedTransportTypes:
    - webrtc
  sip:
    enabled: false
    host: 127.0.0.1
    port: 0
    path: /voice/sip/webhook
    standardWebhookSecretRef: openai-webhook
    issuer: operator-configured-issuer
    audience: talon-incoming-sip
    publicKeys: {}
    endpointMappings: {}
  allowedToolNames: []
  allowedMcpServerNames: []
```

`voice.persona` selects an existing normal persona. Its backend model, ordinary
tools, skills, and configured MCP servers are used through the same
`AgentRunner` path as text work. The selected persona's configured provider (or
the agent-runner default) is authoritative and must be enabled; the provider's
normal OAuth and native-tool restrictions remain in force. The persona's
`model` is the backend model. `voice.model` is the separate live voice model
sent to the live provider. Approval-gated capabilities are unavailable because
voice has no interactive approval channel, and unproven MCP servers fail
closed.

The old `voice.allowedToolNames` and `voice.allowedMcpServerNames` fields are
deprecated compatibility fields and are ignored. Do not use them to grant
voice access. The selected persona's normal capability policy is authoritative.

When `voice.enabled` is true, `browser-voice` is reserved for Talon's internal
voice channel. Startup rejects a conflicting ordinary channel configuration and
does not overwrite an existing non-voice `browser-voice` database row.

For the reference-only incoming SIP authority and Asterisk setup, see the
[Asterisk guide](voice-asterisk.mdx). SIP delivery authentication and caller
authentication are separate: Talon verifies the Standard Webhooks raw bytes
first, then requires a server-mapped, call-bound Ed25519 endpoint assertion.
Missing, duplicate, expired, revoked, altered, or unmapped assertions are
denied; Caller ID and ordinary SIP headers never grant authority. The durable
SIP boundary reserves decisions and receipts before a future provider accept
callback and never retries an ambiguous attempt.

`publicHost` adds `https://<publicHost>` to the allowed origins and documents
the external URL. It does not change the listener address. Keep the default
loopback `host` when the proxy shares the daemon's network namespace; for a
remote proxy, configure `host` to the address that proxy can reach. Origin,
authentication, and CSRF checks still apply to every listener address.

## Login and session flow

Open `https://voice.example.com/voice/` after the daemon and proxy are ready.
The browser submits the access token once to `POST /voice/login`. Talon
exchanges it for an expiring, opaque `HttpOnly` session cookie and a CSRF
cookie. The login page leaves `Keep me signed in for one year` unchecked. An
omitted or false `rememberMe` value keeps the fixed 15-minute grant; the
explicit true value requests a fixed 365-day grant. There is no sliding
refresh. The access token and raw session bearer are not returned to browser
APIs, written to Web Storage, included in session status, or written to logs.
The server persists only hashed session/CSRF verification values and bounded
technical metadata. Grants survive a normal daemon restart; logout,
credential/owner rotation, and configuration reload revoke the affected
authority and rotate the verification boundary. Mutating requests use the
CSRF cookie and `X-CSRF-Token` header; an unauthenticated request cannot create
a session or reach the queue/provider path.

On every page restore, the browser first calls the read-only auth-status route
with the cookie, even when no retained call ID exists. Only after a valid auth
response does it optionally read the retained call. A missing or stale call
does not log out an authenticated owner; a retained-call 404 clears only the
stale pointer and shows the ready state. A network or server failure preserves
the pointer and shows an English retry message instead of claiming that the
login expired. A different browser cookie context, cleared site data, or a
Safari home-screen context may require a fresh login.

The HTTP boundary exposes these routes:

| Route                               | Purpose                                                    |
| ----------------------------------- | ---------------------------------------------------------- |
| `GET /voice/healthz`                | Unauthenticated health check                               |
| `POST /voice/login`                 | Exchange the configured token for browser cookies          |
| `GET /voice/auth/session`            | Read-only cookie auth status (`authenticated`, `expiresAt`) |
| `POST /voice/logout`                | Revoke the browser login and close its active sessions     |
| `POST /voice/sessions`              | Create an authenticated WebRTC session                     |
| `GET /voice/sessions/:id`           | Read retained session, delegation, output, and usage state |
| `GET /voice/sessions/:id/events`    | Subscribe to authenticated status events with SSE          |
| `POST /voice/sessions/:id/close`    | Hang up or close a session                                 |
| `POST /voice/sessions/:id/playback` | Report output playback state                               |
| `POST /voice/sessions/:id/telemetry` | Submit bounded browser connection/playback proxies         |

The telemetry route is separate from semantic playback reporting. It accepts
only fixed RTC, audio play-promise, visibility, and interruption categories,
finite browser-local durations/counts, and output IDs that already belong to
the session. Requests require the current origin, login, CSRF token, and the
original session grant revision. The request body is capped at 16 KiB, batches
contain at most 16 samples (256 per call), and each exact grant/call accepts at
most six batches per minute. The browser keeps at most one request in flight
and aborts a request after two seconds; pending samples are discarded during
cleanup. Samples are content-free proxies: a resolved `audio.play()` promise
does not prove that a person heard audio, and a generic stream cannot mark a
particular output as played. Missing, dropped, late, or unassociated
observations remain unknown; they never change durable output playback, call
cleanup, retries, provider actions, or backend execution.

The browser sends a transport offer. The server chooses the configured persona,
provider, live model, output voice, tools, and MCP policy from the current
login. Provider events become bounded context snapshots, then durable voice
delegations on the ordinary queue and `AgentRunner` path.

Transport and live-engine capabilities are selected from trusted daemon
configuration. Talon rejects a combination when a required capability is
unsupported or unproven before it creates the provider session. The browser
shows a connected call only after both the actual RTC connection and the live
engine readiness event are observed; an optimistic server lifecycle status is
not sufficient. The generic boundary also has variant descriptors for future
verified SIP references and audio streams, but this browser deployment enables
WebRTC only.

Restoration can reopen retained read-only status/history streams, but it never
requests microphone permission, creates a peer or paid audio session, connects
a provider, enqueues backend work, or replays old work automatically. A
remembered login is browser authentication only; it is not a remembered live
audio connection. Background/lock-screen audio and physical iPhone cookie
retention remain unverified and are not promised.

## Lifecycle and limits

Talon stores session, delegation, bounded prompt fragments, policy, usage, and
finalization state in SQLite. The owner/persona pair uses one durable voice
thread across calls. Prompt history is bounded by
`DEFAULT_VOICE_HISTORY_ROWS` and `DEFAULT_VOICE_HISTORY_CHARACTERS`; a
restart recovers that history without replaying completed queue work. A
transcript correction supersedes the earlier context before queue claim; it
must not replay an already claimed delegation. Older calls and messages from
other channels are not imported automatically.
When the live provider reports a delegation, the first notice remains
provisional until a 1,000 ms quiet interval has passed after the latest
meaningful captured USER signature or safety classification change. A fixed
5,000 ms collection deadline starts when that notice is received and never
extends. An initial safe snapshot still waits for quiet; an unsafe snapshot
remains pending at quiet expiry so a valid late transcript can settle before
the absolute deadline. At absolute expiry, a safe but unsettled snapshot is
invalidated and uses the normal clarification path. This is local policy, not a
completeness proof, and it does not depend on an undocumented response-
completion event.

Later notices require a fresh user turn and cannot reuse an earlier utterance.
Late assistant transcript deltas, completion timing, progress speech, and
notification speech do not rewrite an admitted request; user corrections,
ambiguous timing, truncation, and provider replay conflicts remain unsafe. A
transcript that arrives after first publication or expiry is treated as a late
change and fails closed rather than thawing that request. Optional diagnostics
contain only local opaque correlation IDs, fixed event/reason values, bounded
durations, counts, and an observation-scope marker. Close summaries add fixed
availability, opened, finalized, close-requested, and observation-duration
fields. They exclude transcript, prompt, provider ID, payload, error, hash, and
credential data; a zero observed-delegation count describes only the observed
window and does not prove that no provider event occurred before observation
began. These rules do not treat the provider offset as proof that a user turn
was complete and do not claim provider-specific live audio timing or causal
attribution.
Policy is checked again before execution, so a revoked login or changed
generation/policy prevents new backend work. A hangup skips unclaimed work and
retains the result of work that was already claimed or running. Output state
records execution, delivery, provider acknowledgement, and browser playback
separately, so a late result remains inspectable after the call is closed.

The configured session lifetime, concurrent-session limit, and session-creation
rate limit are bounded by the `voice` settings. Retained voice rows do not
contain raw audio. The current runtime has no automatic voice-row TTL cleanup;
operators should include the SQLite voice tables in their local data retention
and backup policy.

## Cost and privacy

The live provider receives the audio and live transcript data required for the
call. Provider-side cloud retention and deletion are controlled by that
provider's account and API settings, not by Talon. Talon does not claim to
delete or control provider-side retention.

Local SQLite stores bounded prompt snapshots and output text needed for session
recovery and audit. There is no automatic TTL cleanup for durable voice rows;
include the SQLite voice tables in the operator's retention and backup policy.
Raw audio is not persisted in the voice schema. Set
`voice.usdPerMinute` only when the operator has a current provider rate; it is
optional and has no default. With a configured rate, Talon estimates voice cost
from cumulative provider-reported seconds. Final provider usage does not
confirm billing, so that estimate remains `estimated`; when that rate has
known usage but an incomplete close, the status is `incomplete`, and no
configured rate is `unavailable`.
Talon never fabricates a voice dollar amount from token totals. Backend cost is
reported only from the AgentRunner run accounting and is kept separate. Voice
observations across AgentRunner, provider tool events, the host-tools bridge,
and nested sub-agents use a server-owned redaction context: transcripts,
prompts, tool arguments/results, and free-form errors are excluded from
Langfuse. Correlation identifiers are bounded to 256 characters and
allowlisted metadata to 4096 UTF-8 bytes. Native AI SDK telemetry is disabled for
voice descendants, and observation setup/update/export failures are best effort
without retrying the underlying work. Local database and operational logs may
still contain sensitive bounded text.

The server also keeps a bounded, content-free lifecycle view when voice is
enabled. It correlates the existing thread, call, delegation, queue, run, and
output IDs through call creation and provider setup, adapter receipt,
context-settled publication, admission/enqueue/claim, backend-provider start,
durable result, output offer, provider acknowledgement, and closure. Receipt and
publication are separate stages, and each duration uses the server's monotonic
clock; browser playback and cross-clock latency are not inferred here. The
facade is no-op when observability is disabled, retains at most 64 call handles,
256 milestones, 128 delegations, and 256 outputs per call, and keeps completed
call correlation for 60 seconds. Exporter failures or saturation drop telemetry
only. Missing or restarted context is unknown; late and unassociated timing is
excluded from duration denominators without rewriting a known observed outcome.
This instrumentation never waits for export or changes queue execution, provider
actions, delivery, retries, or cost/billing status; p50/p95 values are computed
only from known same-process durations with their known-sample count.

## Validation boundaries

The repository includes an offline integration harness using actual daemon
bootstrap, `BrowserVoiceServer`, cookie/CSRF authentication, SQLite voice
migrations, `VoiceSessionService`, the durable bridge, queue, channel
connector, OAuth resolver, and `AgentRunner`; only the live provider and
external backend command are fake. It covers normal persona/provider selection,
permitted `channel_send`, approval denial including a direct bridge attempt,
shared-thread recovery across restart, and no old-work replay. Browser UI
checks cover login, denied microphone handling, mute/hangup/restart, retained
closed sessions, a 390px viewport, and console errors against integrated build
assets.

Those checks do not establish a physical iPhone/Safari call, a paid live
provider call, or provider-specific transcript timing in a live audio session.
Run those separately before treating external-provider or mobile acceptance as
complete.
