# Installation

Talon runs as a native Node.js daemon. No Docker required to get started (though Docker is used for agent sandboxing when enabled).

## Prerequisites

- **Node.js 22+** — Talon uses `process.loadEnvFile`, which requires Node 22
- **Claude Code** — the default agent provider. Install and authenticate it: `npm install -g @anthropic-ai/claude-code`
- **SQLite** — ships with `better-sqlite3`, no separate install needed
- **Git** — to clone the repo

Check your Node version:

```bash
node --version  # must be v22.0.0 or higher
```

## Clone and build

```bash
git clone https://github.com/ivo-toby/talon.git
cd talon
npm install
npm run build
```

The build step compiles TypeScript to `dist/` and copies SQL migrations. Both `dist/index.js` (daemon) and `dist/cli/index.js` (talonctl) are produced.

## Verify the build

```bash
node dist/cli/index.js --version
```

You should see the talonctl version string. If you get a module error, confirm Node 22 is active.

## Initial setup

Run the interactive setup wizard. It checks your environment, creates the `data/` directory structure, and generates a starter `talond.yaml`:

```bash
npx talonctl setup
```

The wizard walks through:

1. Environment check (Node version, Claude Code availability)
2. Data directory creation
3. Config file generation with sensible defaults

After setup, run `talonctl doctor` to validate everything:

```bash
npx talonctl doctor --config talond.yaml
```

Seven checks run — OS compatibility, Node version, Docker (if using sandbox), directory structure, config syntax, pending migrations, and deep config validation. Fix any failures before starting the daemon.

## Apply database migrations

```bash
npx talonctl migrate --config talond.yaml
```

This creates the SQLite database at `data/talond.sqlite` and applies all schema migrations.

## Start the daemon

```bash
node dist/index.js --config talond.yaml
```

Or via npm:

```bash
npm run talond
```

The daemon logs to stdout in structured JSON. Set `logLevel: info` in your config for normal operation; use `debug` when debugging connector issues.

## Systemd service (Linux servers)

For production, run Talon as a systemd service:

```bash
sudo ./deploy/install-service.sh
```

The install script detects your username, home directory, and Node path, then generates `/etc/systemd/system/talond.service`. It reads environment variables from `.env` in the project root.

```bash
# Start and enable on boot
sudo systemctl enable --now talond

# Follow logs
journalctl -u talond -f

# Reload config without restarting
npx talonctl reload
```

The service unit includes security hardening: `NoNewPrivileges`, `PrivateTmp`, `ProtectKernelTunables`, and `SystemCallFilter=@system-service`.

### Custom install options

```bash
sudo ./deploy/install-service.sh --user talon --dir /home/talon/talon
```

## Wake-only mode (timer)

For low-traffic deployments, use the systemd timer to wake the daemon periodically instead of running it continuously:

```bash
sudo cp deploy/talond-wake.service /etc/systemd/system/
sudo cp deploy/talond.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now talond.timer
```

Default wake interval is 5 minutes. Adjust `OnUnitActiveSec` in `deploy/talond.timer` to change it.

## Secrets and environment variables

Never hardcode credentials in `talond.yaml`. Use `${ENV_VAR}` placeholders and load them from `.env`:

```bash
# .env
TELEGRAM_BOT_TOKEN=your-token-here
SLACK_BOT_TOKEN=xoxb-...
SLACK_APP_TOKEN=xapp-...
```

Talon loads `.env` automatically at startup via `process.loadEnvFile`. Check for missing variables any time with:

```bash
npx talonctl env-check --config talond.yaml
```
