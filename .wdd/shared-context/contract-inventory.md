# Signal channel contract inventory

Scope: `signal-channel`. Baseline: signal-cli **v0.14.9**, commit
`3997429779095ff3a2d64c877126e84fce9852aa`.

`R/` below expands to the active epic's
`research/signal-cli-v0.14.9/`. These are byte-identical upstream reference
files, with original line numbering; `R/provenance.json` records their URLs and
SHA-256 hashes. The snapshot is research evidence, not a runtime dependency.
Only source passages actually opened are cited. Source inspection is not a
live-device test.

## Repository contracts carried into the design

| Concern | Read observation | Citation |
| --- | --- | --- |
| Durable handoff gap | Existing key returns duplicate before enqueue; message insert and queue enqueue are separate | `src/pipeline/message-pipeline.ts:140-171,210-248` |
| Same connection | Bootstrap constructs message, queue, thread and routing repositories from the same DB; BaseRepository exposes a transaction helper | `src/daemon/daemon-bootstrap.ts:154-170`; `src/core/database/repositories/base-repository.ts:27,78-82` |
| Typed errors inside transactions | Message insert and queue enqueue return Result errors instead of throwing. Returning an Err from a SQLite transaction callback alone will not force rollback; the new transaction boundary must convert it into an internal rollback and return the original typed error | `src/core/database/repositories/message-repository.ts:88-102`; `src/core/database/repositories/queue-repository.ts:143-151`; `src/core/database/repositories/base-repository.ts:78-82` |

| Generic send recipient | Explicit recipient, schedule origin, then real thread external ID; connector.send receives the selected external ID | `src/tools/host-tools/channel-send.ts:195-249` |

## Validation still required

- Real linked-device provenance, including self-message duplicates and echoes
  preceding an RPC response. Device metadata must be freshly established after
  relinking; no field is invented in the JSON device list.
- Target-platform binary, Unix socket permissions and mounted-socket behavior.
- Current version's actual notifications, partial sends, rate-limit envelopes,
  account-loss signals and text-only receive configuration.
- Offline/bridge restart behavior. No source-derived fixture is recorded as
  live proof, and no stronger delivery guarantee is inferred from this inventory.
